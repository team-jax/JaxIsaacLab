# 카메라 정보 (deploy 25550 기준)

큐브를 재는 카메라의 설치 사양, 좌표 변환, 정책이 카메라에서 받는 값을 모았습니다. 좌표계와 관측의 자세한 정의는 [README.md](README.md) 4절(좌표계), 7.1절(조회표), 8.1절(관측)에 있습니다.

## 1. 설치 사양

| 항목 | 값 |
|---|---|
| 카메라 | 휴대폰(거치대에 고정) |
| 높이 | 바닥에서 **1.2005 m** = 책상 윗면(0.735 m) + 0.4655 m = 어깨축 − 7 mm |
| 앞뒤 위치 | 프로파일 중심선(URDF `base_link` 원점)에서 앞으로(베이스 −x) **117.7 mm**. 프로파일 앞면에서 77.7 mm, 뒷면에서 157.7 mm |
| 좌우 위치 | 가운데(베이스 y = 0) |
| 방향 | 앞(베이스 −x)을 보고 **45° 아래로** 기울임 |
| 시선이 책상 윗면과 만나는 곳 | 프로파일 중심선에서 앞으로 0.583 m |

- 높이와 앞뒤 위치는 2026-11-12 CAD 측정값(URDF_1109 참고)입니다. 이전 값은 1.215 m, 153 mm였습니다.
- **잰 점은 휴대폰 거치대의 우측 아래 꼭짓점입니다.** 렌즈 중심이 그 꼭짓점에서 얼마나 떨어져 있는지는 아직 반영하지 않았습니다. 렌즈 위치를 재면 이 값을 고쳐야 합니다.
- 좌우 위치와 45° 기울기는 이번에 재지 않았고, 이전 사양(2026-11-11)을 그대로 씁니다.

## 2. 카메라 좌표계 (공통 좌표)

Isaac, 팀원 MuJoCo, 실물이 같이 쓰는 기준입니다.

- **원점:** 카메라
- **축:** 로봇 베이스 축과 같음. x = 뒤(−x가 앞), y = 베이스 y, z = 위
- 어깨 피치축은 카메라 좌표로 (−0.032, 0, +0.007) m입니다. 어깨축이 카메라보다 32 mm 앞, 7 mm 위에 있습니다. Isaac 문서 좌표와 팀원 MuJoCo 좌표에서 바꿔도 같은 값이 나와, 두 장면이 같은 로봇 위치를 가리키는 것을 확인했습니다.

### 2.1 카메라 원본 값 → 카메라 좌표

카메라 광학 좌표(OpenCV: x = 영상 오른쪽, y = 영상 아래, z = 시선 방향)로 잰 점 `p_opt`는 아래처럼 바꿉니다.

```
p_c = R_OPT · p_opt

R_OPT = [[0,  0.7071, -0.7071],
         [1,  0,       0     ],
         [0, -0.7071, -0.7071]]
```

- 영상 오른쪽 = 베이스 +y
- 영상 아래 = (0.707, 0, −0.707)
- 시선 = (−0.707, 0, −0.707)

### 2.2 다른 좌표계와의 변환

| 출발 | 카메라 좌표로 |
|---|---|
| 이 문서(README)의 월드 좌표 p | `d = p − (0, 0.1277, 1.2005)` → `p_c = (−d_y, d_x, d_z)` |
| Isaac 시뮬 기록(`handover_state.json` 등) | z에 +0.0525를 더해 문서 좌표로 바꾼 뒤 위 식 |
| 팀원 MuJoCo(`JAX_SETUP=real`) | `p_c = p − (0.3723, 0, 1.2005)` (= x − 0.49 + 0.1177) |

방향(쿼터니언)은 로봇 베이스 회전(z축 −90°)의 역회전을 앞에 곱하면 카메라 좌표 방향이 됩니다.

변환 코드는 `ik_merge/camera_frame.py`에 있습니다(이 저장소 바깥).

## 3. 정책이 카메라에서 받는 값

### 3.1 큐브 위치 → 관측 28–30

카메라 좌표의 큐브 중심 `p_c`에서 바로 계산합니다(책상이 기준 높이일 때).

```
관측 28 = x_c − 0.1277
관측 29 = y_c − 0.115
관측 30 = z_c + 0.9005
```

- 일반식: 28 = x_c − (0.01 + 앞뒤 위치), 30 = z_c + (높이 − 0.3). 카메라 위치를 다시 재면 이 두 상수만 바뀝니다.
- 검산: 기준 위치 큐브(문서 좌표 (−0.285, 0.26, 0.76))는 카메라 좌표 (−0.132, −0.285, −0.441)이고, 관측 28–30은 (−0.26, −0.40, 0.460)입니다(README 8.1과 같음).
- 31–33(큐브 속도)과 34–36(큐브 − 손끝 중점)도 같은 큐브 위치에서 나옵니다. 손끝 중점은 보낸 목표각으로 순운동학을 풀어 구합니다.
- **이 값들은 매 제어 스텝(60 Hz) 들어갑니다.** 쥐는 동안과 드는 동안에도 큐브를 계속 추적해야 합니다. 손가락에 가려지는 구간을 어떻게 메울지(마지막 값 유지, 손 기준 추정 등) 정해야 합니다.

### 3.2 큐브 위치 → 사전 파지 조회표

- 조회표 입력은 큐브 기준 위치(문서 좌표 (−0.285, 0.26))에서 잰 오프셋 (dx, dy)입니다(README 7.1).
- 카메라 좌표로는 `dx = y_c + 0.285`, `dy = −x_c − 0.132`입니다.
- 들어올리기를 시작하기 전에 한 번 잽니다.

### 3.3 큐브 각도 → 관측 43–44

- 큐브의 세로축 회전각 ψ_cube를 한 번 잽니다. 위에서 보아 반시계가 +입니다.
- 정육면체라 90° 차이는 같은 값이므로, −45° – +45° 범위의 값 하나만 주면 됩니다.
- 카메라 좌표(베이스 축)로 잰 각도는 90° 주기로 보면 월드 기준 각도와 같아서 그대로 써도 됩니다.
- `ψ = ψ_cube − θ(dx, dy)`이고, 관측 43 = sin(4ψ), 44 = cos(4ψ)입니다. θ는 `hand_theta_v65.pt`를 (dx, dy)로 보간한 값입니다(README 8.1).
- 들어올리기 전에 한 번 재고, 에피소드 내내 그 값을 씁니다. 쥐는 동안 큐브가 돌아가도 고치지 않습니다.

### 3.4 넘겨줄 때 큐브 각도

- 넘겨주는 순간의 큐브 자세는 `handover_state.json`의 `cube_quat_wxyz`(월드)로 넘깁니다.
- ㄴ자는 모든 경우 같은 자세이고, 손 안의 큐브 각도는 맞추지 않습니다. 정면 맞추기는 MuJoCo 쪽 IK가 운반 중에 합니다.

## 4. 학습에 넣은 카메라 오차

| 항목 | 학습 범위 |
|---|---|
| 큐브 위치 | 스텝마다 표준편차 2 mm + 에피소드마다 ±5 mm 치우침. 치우침은 조회표 입력과 θ 조회에도 들어감 |
| 큐브 각도 | 에피소드마다 ±3° 균일 오차 |
| 지연 | 카메라 지연은 따로 넣지 않음(행동 지연 0–67 ms만 있음) |
| 가림 | 넣지 않음 |

카메라 위치 오차 ±1 cm에서도 시뮬 성공률은 93.8%였습니다(README 12절, 이전 배치 기준). 실물 오차가 위 범위를 넘으면 성능이 떨어질 수 있습니다.

## 5. 주의: 지금 배치에서 큐브가 시야 가장자리에 있음

카메라는 앞(베이스 −x)을 봅니다. 팀원 MuJoCo 책상이 그쪽에 있습니다. 그런데 deploy(Isaac) 배치의 큐브 범위는 베이스 −y 쪽에 놓여 있습니다. 카메라에서 본 방향을 계산하면 아래와 같습니다(큐브 중심, 책상 기준 높이).

| 큐브 위치 (dx, dy) | 카메라 좌표 (m) | 시선에서 벗어난 각도 | 영상 왼쪽 / 아래 |
|---|---|---|---|
| (+0.02, +0.28) 먼 쪽 | (−0.412, −0.265, −0.441) | 24° | 24° / 2° |
| (−0.06, +0.28) | (−0.412, −0.345, −0.441) | 30° | 30° / 2° |
| (+0.02, 0) | (−0.132, −0.265, −0.441) | 40° | 33° / 28° |
| (−0.06, 0) 가운데 | (−0.132, −0.345, −0.441) | 45° | 40° / 28° |
| (−0.14, 0) | (−0.132, −0.425, −0.441) | 50° | 46° / 28° |
| (−0.06, −0.28) 가까운 쪽 | (+0.148, −0.345, −0.441) | 69° | 59° / 64° |

- 가까운 쪽(dy −0.28)은 카메라보다 뒤, 거의 바로 아래(깊이 0.21 m)라 휴대폰 화각으로는 보기 어렵습니다.
- 가운데 줄도 시선에서 40–50° 벗어납니다.
- 참고로 팀원 MuJoCo 배치의 큐브 범위는 시선에서 5–28°라 화각 안에 들어옵니다.

실물 설치 전에 확인할 것:
1. 쓰는 휴대폰 카메라의 화각(가로·세로)
2. 실물 책상이 어느 쪽에 놓이는지(deploy 배치인지 팀원 MuJoCo 배치인지)
3. 큐브를 놓는 범위 전체가 영상 안에 들어오는지. 안 들어오면 카메라 방향을 돌리거나 큐브 범위를 줄여야 합니다.

## 6. 실물 적용 체크리스트

1. **렌즈 위치와 기울기 실측:** 높이와 앞뒤 위치는 거치대 꼭짓점까지 쟀습니다(1절). 렌즈 중심까지의 오프셋과 실제 기울기(45°)를 재서 반영합니다. 설치 각도가 1° 틀리면 50 cm 거리에서 약 9 mm 어긋나, 학습 범위(±5 mm)를 넘습니다.
2. **보정:** 아는 위치와 각도로 큐브를 몇 곳에 놓고, 카메라 값이 2절의 변환과 맞는지 확인합니다.
3. **시야:** 5절을 확인합니다.
4. **추적:** 쥐고 드는 동안 큐브 위치를 매 스텝 줄 수 있는지, 손가락에 가려질 때 어떻게 할지 정합니다.
5. **각도:** 큐브 세로축 각도를 −45° – +45°로 접어서 주고, 오차가 ±3° 안인지 확인합니다.
