### A-14. 학습 속도 20배 저하: 코드 탓으로 잘못 짚었다가 GPU 상태로 정정

> 주제: 5, 6 · 초안 출처: 시기 A (시작 ~ 10-19, Codex 시기)

- 날짜/기간: 2026-10-13, 2026-10-19 (같은 현상 2회)
- 상태 구분: 원인 확인 = 실행·검증됨(nvidia-smi·커널 로그) / 링크 위치 기반 근사 판정 = 구현만 함(속도 효과 입증 안 됨)
- [상황]: (10-13) 사용자 "야 근데 1000it인데 왜 6시간이나 걸려?", "뭐지? 지난번이랑 차이가 뭐길래 속도가 느리지", "나는 그 시간을 바꾼적이 없는데"(KST 10-13 17:04~17:24). (10-19) 실험 2 `model_999`에서 v7 파지 task로 1000 it 이어 학습을 시작하자 약 0.88 s/it → 18.6 s/it.
- [목표]: 속도 저하가 학습량 증가인지, 시뮬 병목(접촉 센서)인지, GPU 전력 제한인지 구분.
- [해결]:
  - 10-13: 저장 설정 비교(사용자 지시로 학습 중단·설정 변경 없이) — env 7056, 24 step/env, dt 1/120·decimation 2, epochs 4/minibatch 8, iteration당 환경 스텝 169,344로 **같음**. 수집 1.095→19.335 s, 학습 0.160→4.474 s(약 28배). GPU 사용률 100%인데 **6.92 W, 전력 제한 15 W(기본 80 W), P8·SM 210 MHz**. Codex가 안내한 `nvidia-smi -pl 80`은 이 노트북에서 지원 안 됨(잘못된 안내 인정), `nvidia-powerd` 확인. 사용자 재부팅(17:31) 뒤 재개 중 **Xid 31(MMU Fault) → Xid 154(재부팅 필요)**로 CUDA 초기화 실패 → 다시 재부팅, 사용자 터미널에서 `model_1000.pt`부터 재개.
  - 10-19: 처음에 PhysX 접촉점 버퍼 조회를 원인으로 보고 **링크 위치와 접촉력 방향으로 판정하는 근사**로 바꿨지만 속도 그대로. nvidia-smi에서 RTX 4060 Laptop **P8, 210 MHz, 약 6 W** → "접촉점 조회만이 원인이라고 결론 내린 것은 잘못" 정정, 느린 학습 중단. 사용자가 재부팅(Claude 첫 대화 KST 10-19 19:09 "재부팅했단다").
- [결과]: v7 1000 it 학습과 파지 평가 영상은 **없음**(`grasp_after_lift_exp1_1k`, `_fast_1k` 폴더는 몇 iteration만). 사용자의 "파지 학습이 조준도 보완할 것" 가설은 이 시기에 **검증되지 않음**. 근사 접촉 판정은 실제 안쪽 면 여부를 직접 보지 못하므로 GPU 정상 상태에서 정확도·비용을 다시 비교해야 한다고 남김. 이 경험은 이후 메모 `reference_gpu_p8_throttle.md`("학습 20배 느려지면 코드보다 GPU 상태를 먼저", 재부팅 시 P0 2250~2445 MHz 복구)로 정리됐다(정리 주체는 시기 B의 Claude).
- 근거: 사용자 발화 KST 10-13 17:04·17:09·17:10(`sudo nvidia-smi -pl 80` 출력 붙여넣기)·17:14·17:24·17:31·19:14; Codex 답변 KST 10-13 17:13·17:23·19:11·19:12·19:14, 10-19 19:06; `logs/rsl_rl/one_arm_jax_minimal_stage1_cube5cm_v3_5k/`(17-33-43 run이 `model_1000`에서 멈춤, 19-15-17 재개 run `model_4999`), `jax_v2_1006_pregrasp_pose_v6/2026-10-19_18-57-00_grasp_after_lift_exp1_1k`, `..._19-02-51_..._fast_1k`, `logs/rsl_rl/jax_v2_grasp_after_lift_exp1*/train_console.log`; `CODEX_JAX_RL_HISTORY_THROUGH_2026-10-19.md` 6절; 메모 `reference_gpu_p8_throttle.md`.
- 참고 자료: 기록에서 확인 안 됨.
- 역할: [사용자] 속도 이상 발견, "시간을 바꾼 적 없다"는 사실 확인, 재부팅 / [Codex] 설정 비교·GPU 진단, 잘못된 원인 판단 후 정정.

### B-12. 학습 운영과 평가 방식: 반복 루프, 세이브 포인트·앵커·롤백, 설정 검증, 인프라 문제

> 주제: 5, 6 · 초안 출처: 시기 B (10-19 ~ 10-31)

- 날짜/기간: 2026-10-19 ~ 10-30 전 기간
- 상태 구분: 운영 규칙 — 실행됨 / 일부 도구(감시, print_cfg)는 사고 뒤 도입
- [상황] 하루에 수십 개 run을 돌리며 보상·구조를 바꾸는 상황. 코드는 git 밖(10월 커밋 없음). GPU는 RTX 4060 Laptop 8 GB.
- [해결·운영 방식]
  1. **반복 루프(사용자 지시)**: 10-19 19:24 "현재 상태 확인 → 1000회 학습 → 평가 영상 → 영상 직접 확인 → 목표와 차이 → 코드·로그·평가로 원인 확인 → 필요한 부분만 수정 → 검증 → 재학습 반복". 10-22 "it 더 적게 안돼?"(17:35) → 에피소드 단축, 50회마다 판단. "250회로 돌리자"(19:43) → 이후 기본 사이클 250회. 10-29 "방향 보일 수준에서 끊어서 반복적으로 영상테스트"(17:42) → 200회 단위(`v19_iter.sh`). 10-25 "아이디얼할때까지 반복하고 바로 파지로 자동으로 넘어가줘"(11:00) → 단계 자동 전환.
  2. **사이클 스크립트**(`pre_cycle.sh`, `close_cycle.sh`, `liftrl_cycle.sh`, `gl_cycle.sh`, `raise*_cycle.sh`): 학습 → 로그 지표 3시점 추출 → 정면·측면 영상 자동 렌더. 이어 학습은 RSL-RL `--resume --load_run --checkpoint`. 체크포인트 25회 간격(10-22엔 50회 간격을 모르고 1248회를 기다리다 멈춤 장치가 안 걸린 실수).
  3. **세이브 포인트·앵커·롤백**: 10-19 "우선 지금이 세이브 포인트"(커밋 없이 기록만) → 10-22 "롤백하자. 다 엉망이네" → 10-26 "롤백하자니까 그 물체 파지 잘됏을때 버전으로", "앞으로 여기가 앵커야"(v15 3347) → 10-28 "1494 괜찮은데?" → 10-29 "v18을 엥커로 삼자". 롤백은 `.bak` 코드 스냅샷 + run의 `params/env.yaml` 비교 + 재평가 수치 일치로 확인.
  4. **체크포인트 비교**: 학습 마지막이 아니라 중간 체크포인트가 더 나은 경우가 반복(v8 6775·7050, v22 75, v16 sm3 2350은 붕괴 직전). "이어 학습 vs 새로 학습"은 사용자가 자주 물었다("? 왜 이어서 해", 10-19 23:09; "앞전의 학습을 쓰는게 낫지않아?", 10-20 23:16; "이어서 해도돼? 이미 수렴한거같던데", 10-22 18:58). Claude의 판단 근거: 이어 학습은 이미 익힌 동작 유지, 대신 탐색 폭이 줄어(예: 0.27 vs 0.37) 새 동작을 잘 안 시도.
  5. **설정 검증**: configclass는 클래스 본문의 마지막 대입이 이김 → 손 회전 12·높이 오프셋 0.029·엄지 회전 시작 0.0 같은 변경이 뒤 줄에 덮여 **효과 없는 학습을 세 번** 돌림(Claude가 사용자에게 인정). 이후 `print_cfg.py`로 실제 적용값 확인 후 학습.
  6. **평가 조건(이 시기)**: 16 env 고정 배치(평가 스크립트 `seed_12345`), 64 env(체인·닫기 비교), 256 env(크기·후퇴량 시험), 36 env(책상 9위치 × 4). 학습 로그 지표(7,056 env)와 결정적 평가를 섞어 보고한 경우가 많음. 성공 정의가 단계마다 다름: v8 2.5 cm·15°·0.5 s 유지 / v14·v15 4 cm + 양쪽 접촉(+ 깨끗: 15°·1.5 cm) / v12 위치 오차 3 cm 등(사용자가 승인한 548은 이 판정으로 0%) / v16 쥔 채 4 cm / v22 도착 1.5°·0.5 s 정지. 큐브 위치는 이 시기 내내 한 곳 고정 → 위치 일반화는 검증 안 됨(11-01부터).
  7. **인프라 문제**:
     - GPU P8 저클럭(210 MHz, 0.88 → 18–26 s/it): 10-19(Codex 시기 끝), 10-22 01:47, 10-27 07:57, 10-30 23:40. 재부팅으로 해결, 10-27에는 남은 렌더 프로세스를 죽이자 재부팅 없이 복구. 처음(Codex)엔 접촉 버퍼 코드를 원인으로 잘못 짚음.
     - 학습 중 렌더링 → 8 GB VRAM 부족, 영상 노이즈(10-19 23:14) → "학습 중 렌더 금지".
     - 학습이 295회에서 3시간 멈춤 → CUDA unknown error → 재부팅(10-22 20:32), 로그 120 s 정지 감시(watchdog) 추가. 노트북 절전 뒤 CUDA 999(10-27·10-28).
     - Isaac Sim 시작 직후 간헐 세그폴트 → 사이클 스크립트에 한 번 재시도.
     - `pkill -f`가 Claude 자신의 셸을 죽임(exit 144, 여러 번) → PID로만 종료.
     - 스크래치패드(/tmp)가 재부팅 때 지워져 스크립트 유실 → `artifacts/claude_scripts/`에 보관.
     - 영상 형식: OpenCV mp4v로 만든 영상을 사용자가 거부("? 아이잭랩에 영상 명령어 있잖아 뭘쓴거냐", "ㅇㅇ 무조건 아이작랩 명령어로 만들어. 일관성이 없잖아", 10-19 20:27) → gym RecordVideo, 체크포인트 run 폴더 `videos/`에 저장. 카메라는 녹화 중 고정("ㅇㅇ 고정해서 다시찍어", 22:50), 에피소드 전체("에피소드 처음부터 끝까지 보여줘야지", 10-24 22:24).

### C-16. 평가와 체크포인트 선택 방법이 바뀐 과정 (11-04 ~ 11-07)

> 주제: 5, 6 · 초안 출처: 시기 C (11-01 ~ 11-07)

- [해결·변경 순서]

  5. v49b: 새 설정은 라운드 최고에서 이어감, 포화 설정은 전체 최고에서 재시작.
  6. v50 – v51: 기본 조건이 아니라 실물 대비 조건(지연 + 마찰, 이어 묶음 조건)으로 고름.
  7. v57(11-06): 576 env 한 조건으로 고르면 ±2%p 잡음으로 잘못 고름 → 1152 env 재비교, 순위 = 두 조건 평균.
