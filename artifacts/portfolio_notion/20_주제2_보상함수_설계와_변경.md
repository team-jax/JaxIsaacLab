### A-4. 첫 Stage 1(Reach-and-Grasp-Lift) 학습: 원인 분리, scripted 검증, 리셋 커리큘럼으로 77%

> 주제: 2, 3, 6 · 초안 출처: 시기 A (시작 ~ 10-19, Codex 시기)

- 날짜/기간: 2026-09-24 ~ 09-26
- 상태 구분: 실행·검증됨(256 episode 결정적 평가, 단 로그·체크포인트는 10-10 삭제로 현재 없음)
- [상황]: 사용자가 붙여 넣은 Stage 1 사양(첨부 b3375b50, KST 09-24 17:31): 관측은 `object_xyz + 관절각`만, 행동은 누적 delta joint position, 보상은 **Isaac Lab Lift의 `reaching_object`(1−tanh(d/0.1)), `lifting_object`, `action_rate`** 3개만. 5000 it 학습 결과(`2026-09-25_14-35-03/model_4999.pt`)를 본 사용자: "end-effector가 물체를 제대로 파지하지 못하고 책상 표면에만 닿은 뒤 episode가 끝나는 것처럼 보인다"(KST 09-25 16:21), "근본적으로 팔 리치가 딸린다는거니"(16:29).
- [목표]: 학습 실패 원인이 팔 길이인지, 보상·제어 구조인지 구분하고 실제 grasp→4 cm lift를 학습시키기.
- [해결] (시간 순):
  1. Codex가 기존 구현과 사양 충돌을 정리: 관측에 속도·목표·이전 행동이 들어 있었고, 물체 초기 높이 0.055 m에 절대 문턱 0.04 m를 써서 **들기 전에도 lift 보상이 나올 수 있었다** → 관측 17(물체 xyz + 관절 14), 행동 14(관절별 `이전 목표 + a×0.02 rad`, 관절 한계 clamp), lift 문턱을 초기 높이+4 cm로 수정.
  2. 5000 it 정책 진단: 모든 에피소드가 5초 timeout, lift 0회, 손이 물체에서 25~30 cm 떨어진 책상 모서리로 내려감. 어깨–물체 0.577~0.673 m < 이론 최대 0.733 m라 **팔 길이가 주원인은 아님**. 대신 ① 보상의 EE 기준점이 손가락 사이가 아니라 `rotation_base`(손바닥 관절 원점, 실제 파지 중심과 약 11 cm 차이) ② std 0.1이라 20~30 cm 밖에서 신호가 거의 0 ③ 행동 clip 없음으로 목표각이 관절 한계에 붙음(관절별 clamp 비율 최대 99.6%).
  3. 수정 순서: `grasp_center` 프레임 도입 → 사용자 확인("그러니까 너 말은 std를 수정하자는거지?") 후 **std 0.1→0.2** → 200 it에서 reach 보상 ≈0 → 0.27로 신호 회복 → 행동 clip [−1,1] 추가.
  4. **잘못된 진단과 정정**: "손가락 충돌 메시 중심이 링크 원점에서 68 cm 떨어져 있다"는 보고는 STL 정점에 `<collision><origin>`을 적용하지 않고 계산한 오류였다고 Codex가 스스로 철회(KST 09-25 20:36).
  5. 사용자 지시 "grasp pose가 충분히 안정화될 때까지 자동으로 반복 탐색"(09-25 22:06): scripted 파지 성공 **15/16**, 단일 시험 lift 7.92 cm·2초 유지. 그리퍼를 6관절 개별 명령 대신 **스칼라 1개 → 6관절 협응 매핑**으로 바꿈(행동 9).
  6. 사용자 "1만회정도 돌려볼래 지금 너무 생각이 많아졌다"(22:22) → 10,000 it(9.8억 step) 결과 reach 0.42, lift·grasp **0**. Codex 판단(09-26 11:06): "iteration 부족이 아니라 학습 구조상 수렴 실패". scripted 성공 자세가 매우 좁아 PPO가 희소한 lift 보상을 한 번도 경험하지 못했다.
  7. 추가로 찾은 직접 원인 3개: (a) Isaac Lab 보상은 dt(0.02)를 곱하고 성공 즉시 종료라 weight 15의 lift가 실제로는 0.3만 지급 → **lift weight 150**으로 보정, 상승 속도 보상 5→1. (b) 팔 PD(stiffness 80, damping 4)가 첫 어깨 관절을 목표 −0.660 대신 −0.403 rad에서 멈추게 함 — **scripted 15/16은 팔 상태를 매 물리 스텝 직접 써서 이 문제를 가렸다** → PD 200/10. (c) 0자세 리셋에서 사전 파지 자세까지 가는 경로에 손목–책상 충돌(약 78 N).
  8. 그래서 **scripted 파지 자세 근처에서 시작하는 리셋 커리큘럼**(Stage A 중앙 생성 → Stage B 원래 물체 범위)으로 전환.
- [결과]: 보상 `reach 1.0, pregrasp_pose_error −2.0, grasping_object 0.5, grasped_upward_velocity 1.0, lifting_object 150, action_rate −1e-4`, 행동 9(팔 8 delta + 그리퍼 스칼라 1). Stage A 학습 중 성공 약 99.9%, **Stage B `2026-09-26_12-00-28_stageB_spawn_range_300/model_598.pt` 결정적 평가 198/256 = 77.34%(4 cm 이상)**, timeout 22.66%. 사용자 반응: "오 뭔가 이번엔 유의미하게 나왔네?"(KST 09-26 17:58).
  한계: 이 정책은 **사전 파지 근처 리셋에서만** 동작한다. 0자세(팔 늘어뜨림) 리셋까지 커리큘럼을 넓히자 grasp/lift 신호가 0이라 약 50 it에서 중단 — 이 문제(팔 들어올리기 경로)는 10월 V2 단계와 이후 시기의 스크립트 팔 들기로 이어진다.

### A-5. 들고 2초 유지하기: 자동 fine-tuning 반복과 70% 목표 미달

> 주제: 2, 5, 6 · 초안 출처: 시기 A (시작 ~ 10-19, Codex 시기)

- 날짜/기간: 2026-09-26 ~ 09-27 (10-09 오후까지 일부 계속)
- 상태 구분: 실행·검증됨(256 episode, 고정 seed) / 목표(70%) 미달
- [상황]: 사용자 관찰 "지금 에피소드가 쫌 많이 짧아진 상태인가? 거의 잡자마자 다음 에피소드가 시작되는듯하네"(KST 09-26 18:15) → 4 cm에 닿는 순간 성공 종료라 유지 능력을 볼 수 없었다. 평가 환경만 "4 cm 이상 연속 2초"로 바꾸자, **들고 나서 다시 놓는 현상**이 보였다(사용자 KST 09-26 19:23).
- [목표]: 256 episode 기준 strict 2초 유지 ≥ 70%(가능하면 80%), 기존 접근·파지 능력 보존.
- [해결]: 원인: 들기 후 그리퍼 스칼라 행동이 열림 방향으로 바뀜(`premature_opening` 벌점이 −0.5~−1.3까지 실제 발생), 순간 높이만 맞추면 성공이던 구조. 1초 접촉 유지, 들린 상태 접촉 유지 보상, 조기 열림 벌점, 2초 진행 보상, 에피소드 5→8→12초, 4→6 cm 점진 보상(weight 30) 등을 한 번에 하나씩 fine-tuning하고 256 ep로 평가해 좋아지면 best 갱신, 나빠지면 rollback. 사용자가 "중간 보고 금지, 승인 기다리지 마라, 70% 달성 전 종료 금지"(KST 09-27 16:57) 규칙으로 자동 반복을 지시.
  **주의할 구조**: best 구조에는 "4 cm 진입 시 검증된 lift pose로 팔 목표 고정, 3 cm 진입 시 그리퍼 closed PD target"이 들어 있다(답변 KST 09-26 22:55). 즉 유지 단계의 팔·그리퍼를 **환경이 고정하는 보조**가 포함된 수치다.
- [결과]: strict 2초 유지 10.5% → 42.6%(trial 4) → 51.6%(`model_2800`) → 63.3% → 66.8% → 67.2%(`model_3400`) → **68.4% = 175/256(`model_3599`), drop 10.7%**(KST 09-27 16:57). 이후 stageW 61.7%, X 64.1%, Y 63.7%, Z 62.5%, AA 61.3%로 모두 악화해 폐기. 10-09 오후 기준 "1000회와 500회 추가 학습도 최고 기준을 넘지 못했고, rollback 중 arm hold state 초기화 한 줄이 빠져 마지막 검증이 중단"됐다고 보고(KST 10-09 16:33). 70% 목표는 끝내 달성 못 함. 체크포인트는 10-10 삭제.
  과정 문제: 사용자 "뭐지 너 계속 하고있는건 맞냐 왤케 의심이들지"(KST 09-27 21:44)에 Codex가 "방금 전까지는 다음 학습이 실행 중이지 않았다. 내가 '계속 진행 중'처럼 말한 게 잘못이었다"고 인정. 이 일 직후 사용자는 "실행하지 않은 학습을 실행했다고 가정 금지 … 새 run directory·checkpoint·final iteration이 존재해야" 하는 검증 규칙을 붙였다(KST 09-27 23:30).

### A-10. nominal 동작 기반 보상(v3·v4)과 논문 기반 단순화(v5): 접촉 수치와 실제 파지의 불일치를 진단

> 주제: 2, 6 · 초안 출처: 시기 A (시작 ~ 10-19, Codex 시기)

- 날짜/기간: 2026-10-12
- 상태 구분: v3·v4 = 실행·평가됨 / 진단 = 실행(재학습 없이) / v5 = 구현만 함(수동 검증 실패로 학습 안 함)
- [상황]: 사용자 지시(KST 10-12 08:34): "nominal.mp4에서 보여준 올바른 파지 동작으로 정책이 수렴하도록 … 물체에 접근 → 손바닥과 손가락을 정렬 → 물체 주변에 배치 → 손가락 안쪽으로 감싸며 닫는다". `nominal.mp4`는 관절 궤적 데이터가 아닌 **영상 참고자료**(Codex: "영상에서 관절각은 추정하지 않았습니다").
- [목표]: 손을 벌려 감싸는 순서를 보상으로 유도하고, 접촉 지표가 높은데도 파지가 안 되는 이유를 확인.
- [해결]: v3: 손 방향 정렬, 둘러싸기 배치, 안쪽 접촉, 조기 닫힘 감점, 단계별 보상 비중(Phase). 사용자 지시로 **원인 분석만**(보상 수정·재학습 금지) 진행한 진단에서: 동시 접촉 613스텝 모두 `FingerClosureQuality` 0(distal 평균 0.025 rad, 기준 0.45 rad, 그리퍼 행동 평균 −0.394 = 열림 방향) → 곱셈 구조의 `GraspQuality`가 항상 0. 물체 로컬 좌표로 다시 분류하니 접촉점 1,839개 중 **607개가 윗면 방향** → world Z 기준 "측면" 판정에 윗면 누르기가 섞임. 원인을 A 정책(닫지 않음·상대속도), B 보상 가능성, C 판정 문제로 분류. v4: 감싼 뒤 닫는 점진 보상 + 물체 로컬 좌표 판정. 이어서 사용자가 붙여 넣은 논문 기반 재설계(첨부 690c6bda): Ferreira & Barbosa(2025) `R = −0.1·distance + 10·grasp_success(0.5초 유지)`, OpenAI(2018) 거리 감소량 보상, 2021 synergy space 논문의 단계 구분, Isaac Lab 리셋 커리큘럼 → v5 `ReachProgress + 0.5×GraspPreparation + 10×GraspSuccess − 0.01×ActionRate − 0.1×ExcessForce`.
