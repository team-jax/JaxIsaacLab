### A-6. End-to-End Pick & Place 시도와 목표 축소: "RL은 잡고 4 cm 들어 유지까지"

> 주제: 4, 2, 6 · 초안 출처: 시기 A (시작 ~ 10-19, Codex 시기)

- 날짜/기간: 2026-10-09 ~ 10-10
- 상태 구분: E2E 환경 = 구현·학습·평가됨(실패) / 새 direct 환경 5실험 = 실행됨(0/16) / 역할 재정의 = 사용자 결정, 이후 모든 단계의 범위
- [상황]: (KST 10-09 16:38) 사용자: "reach, grasp, lift 등을 각각 독립적인 최종 목표처럼 다루지 말고, 물체의 현재 위치와 목표 위치를 입력받으면 하나의 강화학습 정책이 … 내려놓는 전체 과정을 한 번에 수행". 새 세션에서 "이전 학습 결과는 유효하게 학습되었다고 보지 않는다 … 현재 코드와 생성된 영상을 직접 확인해서" 판단하라고 지시(KST 10-09 23:50).
- [목표]: 물체·목표 좌표 입력 → 접근·파지·들기·운반·내려놓기를 한 정책으로.
- [해결]:
  1. (10-09) 기존 manager-based 구조에 E2E 환경: 관측 20(물체 xyz + 목표 xyz + 관절 14), 행동 9, 보상 reach 1·grasp 2·lift 4·lift progress 2·transport 18·place 25·release 50·drop −8. 4096 env, 5000 it.
  2. 영상과 보상 대조: 들린 상태에서 **파지·들기 유지 항만으로 스텝당 최대 18점, 운반은 최대 12점**이라 잡은 채 머무는 쪽이 유리할 수 있었다. 운반 보상은 EE가 아니라 **물체–목표 거리**를 쓰고 있음을 확인. 손가락 한 곳만 닿아도 "놓음"으로 판정되는 오류, 물체–목표 최소 거리가 보장되지 않는 리셋 오류도 찾음. 로그상 성공 종료 약 5%는 실제 성공으로 인정하지 않음.
  3. 사용자가 영상을 직접 보고 정리(KST 10-10 14:45): "16개 평가 중 13개에서 다중 손가락 접촉, 6개에서 4 cm lift, 들어 올린 6개 모두 목표 도달 전에 drop, 최종 success 0/16", "핵심 병목은 reach가 아니라 grasp 안정화, lift 이후 grasp 유지…". 이어 "무조건 7056개로 돌릴거고 3000it는 돌릴거야"(14:52), 그리고 실험 단위 규칙(아래 [6] 사례).
  4. `model_5200`에서 이어 실험 3·4(200 it): lift 후 grasp center 유지 보상 → lift 12/16이지만 **12/12 낙하**, 조기 열림 벌점 강화 → 열림 0%지만 lift 5/16, **5/5 낙하**. 서로 다른 수정에서 같은 lift→drop이 반복돼 자동 중단.
  5. (KST 10-10 17:41) 사용자: "야기존에꺼 다 지워 남김없이 URDF만" → 9월 이후 환경·체크포인트·로그 삭제. 사용자 붙여넣기 재설계 지시(첨부 cb6468ec): HER·panda-gym 구조 참고, "PPO만 고집하지 마라, 1순위 SAC+HER". Codex는 goal-conditioned SAC로 시작하되 HER는 첫 구현에서 제외(skrl 2.1.0 사용). 새 `direct/one_arm_jax/env.py`, 관측 43, 행동 9.
  6. 5개 실험(각 100 it, 7056 env): SAC 0/16 접촉; PPO v4 다중 접촉 16/16·판정상 파지 10/16이지만 들기·운반 0/16. 영상: 손이 닿은 뒤 제자리 접촉 반복.
  7. (KST 10-10 21:05, 첨부 e904195e) 사용자 **역할 재정의**: "전체 Pick & Place를 RL이 담당하지 않는다. Vision → 스테레오 카메라 + YOLO → 물체 3D 좌표 … RL → 접근, 세 손가락 안정 파지, 책상으로부터 4 cm 이상 들어올림, 유지 … IK → 추가 lift, 운반, 내려놓기 … Gripper → release". 시뮬은 GT 물체 좌표를 쓰되 관측 구조는 실제 비전 XYZ를 꽂을 수 있게 유지.
- [결과]: E2E 최고 `one_arm_jax_urdf_pick_place/2026-10-09_19-19-49_premature_opening_penalty_500` **17/256 = 6.64%**, 이전 평가 15/256(5.86%)·4 cm lift 72.27%·target 진입 17/256, 1000 it 장기 학습은 10/256(3.91%)·조기 drop 93.82%로 악화해 폐기(Codex 보고, 로그는 삭제됨). 이후 RL 목표는 `Reach → Stable Grasp → 4 cm Lift → Hold`로 축소되었고, target·transport·place·release 보상과 관측이 제거됐다(관측 40 = 운반 항목 제거 + 압력 3). 이 역할 분담(RL 다음은 IK/다른 모듈)은 이후 팀원 MuJoCo·IK 모델로 넘겨주는 구조의 출발점이다.
- 근거: Codex 답변 KST 10-09 16:43·16:47·18:52·23:37·23:53, 10-10 14:51·15:10~17:03·17:58·20:06·21:33; `artifacts/orca_codex_conversation_2026-10-18.md` 188·194·623행; 첨부 `cb6468ec.../Pasted text.txt`, `e904195e.../Pasted text.txt`; `logs/skrl/one_arm_jax_pick_place_v1~v5/2026-10-10_*`(현재 남아 있음, `v4/.../checkpoints/agent_2400.pt`가 당시 최선 기록).
- 참고 자료: 사용자 지시문이 HER(Andrychowicz et al. 2017), panda-gym PickAndPlace, "Task Decomposition and Dedicated Reward System", "Vision-Based Robotic Object Grasping"(YOLO) 등을 참고하라고 명시. **실제 적용**: goal-conditioned 관측 구조(achieved/desired goal, 상대 위치)와 SAC 선택까지. HER relabeling은 구현하지 않음. 논문들의 서지 정보는 지시문에 제목 수준만 있어 정확한 출처 확인 필요.
- 역할: [사용자] E2E 목표 설정, 영상 판독 결과 정리, 전체 삭제·재설계 결정, Vision/RL/IK 역할 재정의 / [외부 ChatGPT 가능성] 재설계·역할 지시문의 원천(지시문 안에 출처 표시 없음, 확인 필요) / [Codex] 구현·실험.

### A-11. 최소 환경 `one_arm_jax_minimal`: 보상을 3개로 줄였더니 드러난 문제들

- 상태 구분: 실행·평가됨(각 실험 16 env 고정 seed 영상)
- [상황]: (KST 10-12 17:52) 사용자: "다른 ChatGPT 대화에서 지금까지의 학습 실패 원인과 향후 개발 방향을 논의했고 … 로봇 모델과 정상적인 물리·제어 구성은 유지하고, 강화학습 환경은 최소한의 구조로 다시 설계". 기존 `one_arm_jax`는 보존. (18:03) "첫 번째 Baseline 보상식: `R = ReachProgress + 10 × Success − 0.01 × ActionRate` … 거리 보상은 단순히 가까운 곳에 머무르며 점수를 쌓는 구조가 되지 않도록 … 수동 파지 성공을 학습 시작의 필수 조건으로 요구하지 않는다." (23:36) "분석과 검증을 반복하면서 개발 진도가 지나치게 느려졌다 … 과도한 사전 검토 없이 실제 구현과 학습을 우선".
- [목표]: 해석 가능한 최소 보상으로 "손가락을 벌린 채 접근 → 감싸 닫기 → 0.5초 유지"를 학습.
- [해결/결과] (시간 순):
  1. v1(5000 it): 손가락이 열리지 않고 물체 위를 누름(사용자 KST 10-12 23:36 지적).
  2. v2 열린 손가락 시작 + 손가락 게이트(5000 it, `open_gate_v2/.../model_4999`): 파지 영역 진입·세 손가락 유효 접촉·안정 파지 모두 **0/16**, 옆에서 밀거나 기울임.
  3. (KST 10-13 16:37) 사용자 확정: 물체는 **한 변 0.05 m 정육면체**, InnerContact는 "정육면체 로컬 좌표 기준 옆면 … 압력 증가에 따른 보상 증가는 금지 … 세 손가락이 서로 다른 방향에서 지지하는 접촉을 우대 … 상단을 누르는 접촉은 제외".
  4. v3 5 cm 큐브(5000 it, `cube5cm_v3_5k/2026-10-13_19-15-17/model_4999`): 사용자 "ㅈ같이 학습됐네. 뭐가 문제지"(KST 10-13 23:18). 16개 모두 약 49스텝에 **큐브를 책상 밖으로 밀어 떨어뜨림**(큐브 y 0.076→0.424 m, 책상 끝 0.35 m). 0 행동이면 큐브가 그대로라 학습된 행동임을 확인. 원인: 접근 보상은 손–물체 거리만 봐서 밀어도 손해가 없고, 손가락 게이트 미진입으로 성공 보상이 한 번도 켜지지 않음.
  5. 사용자 판단(KST 10-13 23:29~23:39): "약간 Termination_Penalty 같은게 있어야할거같지않아?", "처음부터 손가락을 벌리고 잡는 형태가 가장 이상적이다 라고 상정 … 근데 영상에선 발톱으로 누구 치려는것마냥", "손목이 아래로 감에 따라 손가락도 아래로 가잖아 그러니까 점마를 밀치지", "Termination Penalty와 손가락 내부의 접촉 보상, 파지자세잖아"(Codex가 문제를 다르게 요약하자 바로잡음). 사전 파지 자세 정의(23:44): 세 손가락 접촉부가 좌·우·상단면을 향하는 3점 파지.
  6. v4 three-face(5000 it, `three_face_v4_5k/2026-10-14_00-16-16/model_4999`): 큐브를 밀지는 않지만 **손을 빼고 움직임을 줄이는 쪽으로 수렴**(접근 0/16, 사전 파지 품질 0.057→0.021, 행동 std 0.367→0.076).
  7. 사용자 가설 "물체에서 멀어지려고 하는 시도가 … Termination_penalty가 강해서인거 같은데"(KST 10-14 08:02) → Codex가 로그 확인: `failure_termination` 최대 평균 0.00026으로 **주원인이 아님**(가설 기각, 근거 수치 제시).
  8. **사용자가 찾은 원인**: "아니 다가갔을때 보상이 음수가 되는경우 말하는거다"(KST 10-14 08:12). Codex가 처음엔 다른 요점으로 답했다가 인정: 접근 보상 `0.99 × Φ(다음) − Φ(현재)`(γ<1인 potential shaping)은 **큐브 가까이 가만히 있어도 매 스텝 작은 음수**라, 성공 보상을 거의 못 받는 상황에선 멀어져 움직임을 줄이는 쪽이 유리할 수 있다. 사용자는 이 문제 설명을 "논문 레퍼런스가 있는 gpt"에게 가져가 확인하겠다고 함(10-14 08:09).
  9. 수정: 손가락 하드 게이트 제거, 접근·사전 파지·접촉 progress 항을 "가까움과 품질에 따른 작은 양의 보상"으로, 후퇴에 작은 벌점. 사용자 지시 "250it정도 돌리고 문제 있으면 계속 수정 … 분석은 250it 끝날때마다 영상으로"(KST 10-14 08:28) → `reward_gate_v5_250` exp1~8(10-14). exp4: 손가락별 접촉 [16,1,16], exp5 손가락 2 방향 반전 → [1,0,16] 악화 후 되돌림, exp6 이어 학습 [16,0,16].
  10. 사용자 "집게발처럼 왼쪽면에 한 손가락, 오른면에 두 손가락으로"(KST 10-14 11:42) → URDF·좌표 확인 결과 손가락 1·2가 한쪽, 손가락 3이 반대쪽(큐브 로컬 X축 대향) → exp8 `two_vs_one_x`: 동시 유효 접촉 **0/16**. Codex 결론: "보상을 더 키우는 것이 아니라 충돌 없이 큐브 양옆에 1개·2개 손가락이 놓이는 초기 손목·손가락 자세를 실제 좌표로 찾는 것"(초기 손가락 끝–큐브 7~20 cm).
